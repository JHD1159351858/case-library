# 后台拖动案例排序

管理员在“现有智能体记录”中按住每行左侧的 ⠿ 手柄，拖到目标行的上半行或下半行，松手即可分别插入到该行之前或之后。出现“排序已保存”后，前台列表使用新顺序，刷新后仍保留。

- 列表顺序独立于“热门 TOP 1–3”。拖动不修改热门配置与徽标，也不改变案例内容、更新时间、展示/隐藏状态。
- 排序在数据库中完成，再应用搜索、筛选及每页50条的分页。隐藏案例保留位置；恢复显示后沿用原排序。
- 已保存的案例优先按拖动顺序展示；新增案例先排在这些案例之后，可再拖动调整。
- 首次保存排序之前，仍沿用原来的热门优先、更新时间倒序规则。
- 保存时暂时禁用拖动。相同位置不发请求；失败或无法确认回执时恢复本页原顺序并提示刷新确认，不自动重复写入。

## 持久化与部署

SQLite 与 PostgreSQL 都使用单行 `agent_order_settings` 保存有序案例ID数组及保存时间。启动时自动幂等创建表，无需手工修改案例数据。部署需要更新并重启后端。

排序与案例共用当前数据库。线上配置持久化 PostgreSQL 时可跨实例和重新部署保留；若使用 `/tmp` 下的 SQLite，仍受临时目录生命周期限制。

## 接口

- `POST /api/agent-order`：仅管理员同源 JSON 请求，正文为 `{ "agentIds": ["case-id-1", "case-id-2"] }`。ID必须存在、不重复，沿用64KB请求限制。返回保存的 `agentIds` 和 `updatedAt`。不会修改热门展示位。
- `GET /api/agents`：沿用原有分页和筛选，增加布尔字段 `manualOrder`，表示是否保存过手动顺序。前台据此显示当前排序规则。
