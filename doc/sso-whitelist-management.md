# 在案例库管理端维护认证中心白名单

## 功能与授权

在案例库管理端展开“认证中心白名单”可查看、添加、启用、停用和删除学校机构 FID 与项目回跳域名。两类名单由认证中心数据库统一保存，影响认证中心接入的所有项目；案例库不建立副本。

操作人必须同时满足：已登录、具有现有案例库管理员权限、超星 UID 命中 `SSO_WHITELIST_ADMIN_UIDS`。其他管理员仍可维护案例，白名单区域只显示当前账号 UID 和未授权提示，不返回名单数据。UID 是 `/api/auth/me` 的 `user.ssoUid`，也会显示在后台白名单区域；它不是手机号或姓名。

## 两端配置

| 配置 | 案例库项目 | 认证中心项目 |
|---|---|---|
| `SSO_CENTER_URL` | 现有认证中心 HTTPS 地址 | 保持原有配置 |
| `SSO_WHITELIST_ADMIN_TOKEN` | 独立随机管理密钥 | 填入完全相同的管理密钥 |
| `SSO_WHITELIST_ADMIN_UIDS` | 允许操作的 UID，逗号分隔 | 无需设置 |

管理密钥至少 32 位可打印 ASCII，推荐独立生成 64 位十六进制随机值。不要使用现有 `SSO_SHARED_SECRET`、管理员密码或管理员会话密钥；相同密钥会被拒绝。真实值只填入部署平台的环境变量/Secret，不提交仓库、不在浏览器表单或聊天中粘贴。原超星登录配置继续保留。

留空 UID 列表默认禁止所有人；仅填写此列表不会把普通用户升级为案例库管理员。既有 `ADMIN_ROLES` / `ADMIN_SSO_UIDS` 规则仍有效。集成缺少密钥时显示“尚未配置”，不会假装名单为空。

## 部署顺序

1. **先更新认证中心项目。** 本仓库 `integrations/chaoxing-center/whitelist-management.patch` 包含认证中心配套修改，按其原有文件合并。补丁基于本地“超星登录认证系统”项目，新增集成令牌校验，仅修改四个白名单 API 的授权入口。使用 Git 应用时运行 `git apply --check --unidiff-zero whitelist-management.patch`，检查成功后再应用。
2. 在认证中心部署配置中新增独立的 `SSO_WHITELIST_ADMIN_TOKEN`，重新部署认证中心。不要修改已有超星应用、数据库和独立后台账号配置。
3. **再更新案例库项目。** 拉取本仓库最新版本，在部署配置中填入相同管理密钥和指定的 `SSO_WHITELIST_ADMIN_UIDS`，保留 `SSO_CENTER_URL`，重新部署。
4. 指定管理员通过原超星登录进入案例库后台，展开“认证中心白名单”，点击“刷新名单”。首次成功读取前不能写入。
5. 添加机构填写数字 FID（1–32 位）；名称可选。项目域名填写例如 `https://example.coze.site`，不含账号密码、页面路径、参数或锚点；备注可选。已有条目可启停，删除需再次确认。

日常修改直接写入认证中心，沿用中心原有缓存失效机制，无需为每次名单调整重新部署。中心原生管理后台仍可独立登录，用于核对记录及恢复配置。

## 接口与失败处理

- 案例库同源 `GET /api/sso-whitelists`：仅授权管理员读取，返回 `fids` 与 `origins`，每项只含标识、名称/备注和启用状态。
- 案例库同源 `POST /api/sso-whitelists`：`kind` 为 `fid` 或 `origin`，`action` 为 `add/enable/disable/delete`，附对应的 `fid/name` 或 `origin/note`。服务端验证会话、指定 UID、JSON 与同源请求。
- 案例库后端固定访问认证中心 `/api/admin/fids`、`/api/admin/fids/:fid`、`/api/admin/origins` 和 `/api/admin/origins/action`；不转发浏览器 Cookie，不开放任意上游地址。管理调用只使用 HTTPS，本机开发允许 localhost/127.0.0.1/IPv6 回环 HTTP。
- 两端服务使用独立 Bearer 令牌。`X-Case-Library-Actor` 由案例库后端从已验证的 UID 进行 `encodeURIComponent` 编码；认证中心验证令牌后解码一次，日志标识为 `case-library:<UID>`。该 UID 是持令牌的案例库服务声明的操作者。
- 写操作不自动重试。正常写入后重新读取名单；若超时或断网导致写入结果不确定，只读回核对，不再次发送写入。读回失败时保留输入和旧列表、锁定写操作，要求刷新确认。
- 403 表示该账号无权管理；503 表示本端配置不完整；认证中心授权失败一般需要核对两端独立密钥及中心配套版本。502/504 表示上游不可用/超时。名单重复、格式错误、条目不存在分别按 409/400/404 提示。

## 验证边界

本地测试覆盖指定 UID 与管理员双重校验、跨站写入拦截、密钥隔离、上游协议和失败读回；中心集成令牌测试、TypeScript 与 ESLint 检查单独执行。真实超星登录、线上认证中心数据库及部署后的联调需要上线后验证。

管理操作沿用认证中心原有审计日志。其现有日志写入为 best-effort，日志失败不会回滚已经完成的名单修改，本次未改成事务审计。中心仪表盘、日志查询、修改密码等接口继续只接受原管理员会话，不能使用集成令牌访问。
